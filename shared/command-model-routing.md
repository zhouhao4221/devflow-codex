# 命令模型路由

执行命令或直接调用对应 skill 时，先按文末命令表选择执行档位。档位决定有界执行工作交给谁，不切换当前主会话模型，也不是 Codex 原生 skill 元数据。主会话通常由用户选用 Astra 或 5.6 Sol：当前是谁，就由谁负责理解请求、确定范围与方案、处理不确定性并最终验收。用户明确指定的模型、预算和运行环境限制优先。

## 档位

| 档位 | 默认执行安排 | 工作类型 |
|------|--------------|----------|
| `economy` | 主会话定范围；`gpt-5.6-luna`，`low` 执行 | 查询、配置、规则化状态流转、发布准备、模板整理 |
| `standard` | 主会话定方案；`gpt-5.6-terra`，`medium` 执行 | 数据聚合成文、接口字段映射、常规代码生成 |
| `primary` | 当前主会话负责决策和验收；有界实施按复杂度交给 5.6 worker | 需求讨论、设计、开发、问题诊断、综合测试和审查 |

`primary` 不等于全部工作都由 Astra 或 Sol 亲自执行。方案明确且可独立验收的常规实施交给 `gpt-5.6-terra`（`medium`）；需要深入多步执行时交给 `gpt-5.6-sol`（`medium`/`high`）；机械查找、测试运行与模板整理交给 `gpt-5.6-luna`（`low`）。主会话若已是 Sol，且任务无法清晰拆开，就直接完成该任务；不为了制造模型分工而派发同模型代理。界面操作和视觉断言等必须由主会话完成的步骤遵循对应 skill。

以上为可用模型下的任务默认值，不根据模型名称推测价格。经济档选择当前可用且能完成任务的最经济模型；缺少价格或账户用量依据时，不声称绝对最低价或具体节省比例。

## 主模型识别

1. 优先使用当前运行时明确提供的**本任务正在使用的模型标识**；可用模型列表、默认设置或子代理可选模型只说明候选，不证明当前主模型。
2. 运行时未提供时，使用用户在当前会话中明确选择的模型。若用户中途切换，以实际运行时状态为准；无法确认切换已生效时，不声称已切换。
3. 两者都缺失时将主模型记为「未知」，保留当前主会话及其推理配置。不要凭回答风格、环境变量、插件缓存或自我猜测识别模型，也不要为了识别而创建任务或修改设置。

识别为 Astra 时，Astra 保留方案、跨文件判断和验收；有界深入实施优先选 5.6 Sol，常规实施用 Terra，机械工作用 Luna。识别为 5.6 Sol 时，Sol 保留同样的主会话职责；能独立完成的常规和机械工作分别交给 Terra、Luna，复杂且无法有效拆分的工作由 Sol 直接完成。识别为其他模型或未知时，仍按任务难度选择已知可用的 5.6 worker，不能声称正在采用「Astra 思考」；不支持覆盖模型时由当前主会话完成。

## 执行入口

1. **主会话先判断**：核对用户目标、授权、项目规则、数据来源和验收标准。已有明确输入直接推进；确实需要业务选择时由主会话处理。`economy` / `standard` 是执行工作默认档位，不把尚未确定的需求、跨文件契约或风险取舍整个交给 worker 决定。
2. **只路由一次**：首次执行命令时查表。已经是该命令的执行者，或命令内部读取 helper skill、调用另一命令的核心逻辑时，在当前模型继续；不能因再次读到路由规则而递归派发。helper skill 本身不另设模型档位。
3. **按独立单元派发**：有界任务使用当前可用的原生子代理接口，显式请求选中的 5.6 模型和推理强度。`primary` 命令由主会话掌握完整流程，再按已定方案拆出实施、定位、测试或成文单元；`economy` / `standard` 命令也只委派边界明确的执行部分。单次工具调用即可完成的小事直接做，协调成本较高或不能独立验收时由主会话继续。需要不同难度的多个单元时，主会话分别选择 worker，而不是让一个执行者递归改路由。
4. **给足执行上下文**：任务说明包含工作目录、当前 skill 的实际路径、原始用户参数、已定方案、用户已授权范围、允许修改的文件、适用项目规范和验收命令，并说明“你是本单元的执行者，不再次进行命令模型路由；遇到未定选择返回主会话”。通常用不继承历史加自包含说明；需要最近讨论时才传少量轮次。当前 `collaboration` 的完整历史继承不能覆盖模型，不能用它声称切到了 5.6 worker。
5. **主会话复核和整合**：worker 返回实际改动、检查结果和未决问题；主会话核对 diff、证据、跨单元一致性及授权，再决定修复或交付。不重复读取全部日志或重做准备。共享目录中保持文件归属，主会话不同时修改执行者的文件。模型分级不扩大原任务范围。
6. **交互和外部操作**：需要用户补充的信息由主会话转达，已有授权不重复询问。提交、推送、切换分支、发布评论、PR、合并、tag、平台 Release 及其他外部写入由主会话按用户授权执行；worker 先返回可核对产物、所需操作和待续步骤。后续准备工作续接原执行者，不从头重派。
7. **不可用时如实回退**：目标模型不可用时选已知合适的可用模型；工具不支持覆盖、无法可靠传递必要上下文、运行环境禁止委派或没有可独立执行的单元时，在主会话继续并简述原因。不能仅写一句“使用 Luna”就声称已切换模型；不为模型路由修改全局配置、安装 agent、创建 App 独立线程或嵌套启动通用 CLI。具体 skill 只有在自身流程明确规定、官方提供非交互只读入口、固定输入范围且定义失败降级时，才可调用对应的专用后端（例如 `rd:pr` 的 `codex exec review --ephemeral`）；这种调用不是模型路由或子代理替代，不能推广到其他命令。
8. **按问题调整**：命令失败、缺依赖和网络错误先按原因处理，不自动升级模型。worker 能力不足时由主会话补齐说明、缩小单元，必要时改用 Sol 或亲自处理；复用已有产物。派发时简短说明单元、请求模型和原因。

## Release

`rd:release` 的默认执行档位为 `economy`，不因流程包含写操作就默认升档。主会话先确认发布范围和用户已有授权，Luna 按 release skill 完成明确的参数解析、版本候选计算、SQL 与回滚产物整理及发布前检查；需要综合成文的 changelog 可由主会话作为单独单元交给 Terra。版本取舍、无法自动推导的回滚和检查失败由主会话判断，worker 返回事实与待补充项，不能猜测。

在提交、分支操作或发布等主会话负责的步骤前返回实际文件、检查结果、待补充项和后续操作。主会话核对后按已有授权继续；需要继续准备时续接原执行者。这里不额外增加发布确认，也不改变 draft、tag 或分支策略。
