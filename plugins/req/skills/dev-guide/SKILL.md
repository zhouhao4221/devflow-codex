# 实现方案参考

在 [dev](../dev/SKILL.md) 需要项目类型对应的上下文或方案细节时使用。状态、分支、实施和验证由 dev 统一管理，本技能不重复执行这些流程。

## 按需查阅

- 模块职责或业务边界：按 [_storage.md](../../shared/_storage.md) 解析需求根目录，读取需求关联的 `modules/<模块名>.md`。
- 分层、目录或开发规范：查阅 `docs/prompt/architecture.md` 的相关部分，缺失时参考 AGENTS.md 和实际项目代码。
- 代码生成约束：需要生成实现时查阅 `docs/prompt/code-generation.md`；项目技能按实际能力与触发范围选择，不全量读取。
- 领域契约：从解析后的 `<requirementsDir>/specs/` 按模块、接口或实体筛选相关文件。readonly 直读主仓自身配置的目录，不使用缓存。只读取与本次实现相关的规约，复用已加载且未变化的内容。

资料缺失时从代码核实可推断的事实；只有缺少会影响正确性的决定才询问，不因缺少某份文档一律停止。

## 后端方案

明确需要的模型/表结构变化、接口契约、文件清单、实现依赖和验收方式，按项目分层职责组织代码。只有真实依赖要求时固定实现顺序。

需要迁移 SQL 时，优先使用项目已配置的 `MIGRATIONS_DIR`，否则检查现有迁移位置（如 `db/migrations`、`database/migrations`）；没有约定时可提出 `docs/migrations` 作为文件位置，不把生成迁移文件视为执行数据库迁移的授权。

## 前端方案

按用户交互功能拆解页面、组件、状态和异常处理。接口匹配优先使用关联后端需求、相关 specs、项目配置的 Swagger/OpenAPI 和现有调用代码；无法核实的契约标注待确认，不将推测写成既定事实。

文件清单和步骤按功能组织；不为纯前端需求生成无关的数据表或后端层级。

## 全栈方案

组合相关的前后端说明，先确定共享契约，再按依赖组织实现与联调。契约未确定的依赖任务等待其确定，独立任务可继续。
