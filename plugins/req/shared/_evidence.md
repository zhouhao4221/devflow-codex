# 子任务返回与验收证据

派发和验收子任务时读取。各角色共用以下字段，角色特有的统计或素材依据接在后面；用简短文本或结构化数据均可，不重复全文和日志。

这是主会话用于验收的摘要，不额外建立任务数据库或强制 JSON 协议。短小的只读任务可合并成一段「任务/状态、已覆盖与缺失、文件位置依据、无改动、验证不适用」。内容快照主要用于并发写入、暂存区审查或跨步骤复用测试证据；普通定位无需为整个仓库生成哈希清单。大型清单放临时文件，返回路径和关键差异。

## 返回契约

| 字段 | 内容 |
|------|------|
| 任务 | 调用方分配的单元标识，便于续接同一任务 |
| 状态 | `DONE`：约定工作已全部交付；`PARTIAL`：只交付部分；`BLOCKED`：缺少材料或条件，无法继续 |
| 范围 | 请求范围、实际覆盖范围、剩余范围；文件审查逐文件列出，不能以「等」省略 |
| 改动 | 相对派发时基线，本轮实际修改/新增/删除的路径；只读任务写「无」，正常生成产物单列 |
| 依据 | 输入版本或快照、验证时相关内容快照、日志/产物路径；未采集则明确写明 |
| 验证 | `PASS` / `FAIL` / `ERROR` / `NOT_RUN` / `N/A`，实际命令、工作目录、必要环境差异、退出码和已知计数；未运行说明原因 |
| 后续 | 未解决项、越界需求和下一步；仍在运行的命令附实际进程/会话句柄 |

任务状态与验证结论分开：仅负责执行测试的任务，命令结束且完整报告失败，可以是 `DONE + FAIL`；负责交付实现的任务，必需验收失败仍有待修复工作，应为 `PARTIAL + FAIL`，验收尚未运行则为 `PARTIAL + NOT_RUN`。`ERROR` 表示命令、依赖或环境等执行错误；无测试需要的只读摘要可为 `DONE + N/A`。进程仍在运行时不能写 `DONE`，也不能将等待窗口结束当作测试失败。工具运行状态以实际工具为准，不用返回文本覆盖。

## 内容快照与复用

- 不可变提交审查记录精确 base/head SHA 和文件清单；暂存区、工作区和未跟踪文件记录相关内容的哈希清单或等价的可核对快照，删除项显式标记。HEAD 相同不代表内容相同。
- 测试依据涵盖被测实现、测试文件、读取的 fixture、相关配置和依赖锁文件；命令/过滤条件与必要运行环境也要一致。只记录修改文件不足以证明测试仍有效。范围无法确定时扩大到相关模块；动态服务数据无法核实时不复用。
- 执行前后检查相关输入是否变化；验证期间有并发修改，或结果缺少可核对的依据时，不能将该结果计为当前状态已通过。先停止冲突写入，再补跑受影响检查。
- 主会话读取实际产物与日志，核对要求覆盖的范围和当前内容。仅无关文件变化不要求全量重跑；相关输入变化则补跑受影响检查。审查遗漏文件只补审遗漏部分，已审部分内容变化则同时补审。

## 写入归属

派发前保留已有改动清单及相关内容基线。共享工作区中的 `git diff` 是所有参与者的合计，不能把它直接当成某个代理的修改清单；还需检查未跟踪文件，并结合任务前后快照及各单元文件归属确认本轮变化。发现范围外改动先核实来源，不自动回滚他人工作；未解决的越界或缺失项不能通过最终验收。
