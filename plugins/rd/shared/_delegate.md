# 子任务委派

在开发、定位、测试、成文和大 diff 摘要步骤按需读取。这里定义的是任务角色，不是已安装的 custom agent；不要把角色名当成工具名或假定存在 Claude 的 Agent/Skill 工具。命令首次执行先按[命令模型路由](./_command-models.md)选择执行档位；已作为该命令执行者时不再次路由。

## 执行方式

- 有可用的 Codex 子代理工具，且存在可独立执行的具体子任务时，用当前工具的实际接口派发。主会话继续处理独立工作，保留需求理解、设计、跨文件判断和最终验收。
- 不支持子代理、运行环境禁止委派或任务很小时，由主会话按同样的角色约束执行；简要注明原因，不阻塞流程。各 skill 的委派步骤均受此条件约束。
- 主代理先按[命令模型路由的主模型识别规则](./_command-models.md#主模型识别)判断当前主会话；再按下方“模型分级”选择当前工具已暴露且可用的 worker 模型与推理强度。尊重用户明确指定的模型、预算和运行时限制。不把 `model` 等字段写入 SKILL frontmatter 或 `openai.yaml`。
- 只读取本次需要的角色文件，把相关约束、工作目录、任务目标、必要素材、允许修改的文件和验收命令放进任务说明。命令路由也只委派有界执行范围，主会话保留用户交互、外部操作和最终验收。
- 派发前判断收益：优先把日志多、搜索范围大且可独立执行的读取工作交给子代理，主会话保留决策上下文。很小的改动、简单命令或协调成本高于收益的任务直接执行；能用一次工具调用批量完成的读取不必另开代理。并行数量服从当前工具的可用容量，不按文件数创建代理。

## Codex 运行时适配

先读本次会话暴露的工具说明，以实际参数、权限和容量为准；下列名称只在对应工具存在时使用，不把某个客户端的接口写成所有 Codex 环境的前提。

- **子代理与 App 任务分开**：当前工作中的委派使用原生多代理工具；`create_thread` / `fork_thread` 创建用户可见的独立任务，不作为子任务派发的替代品。当前没有子代理能力时由主会话执行，不为此自动修改用户配置、安装 custom agent 或嵌套启动 `codex exec`。所属 skill 明确定义的官方只读专用后端不属于子代理降级，例如 `review-pr` 可按自身范围校验调用 `codex exec review --ephemeral`；不得据此把通用 `codex exec` 当成委派机制。
- **上下文按需传递**：支持 `fork_turns` 时，定位、测试和固定方案实施通常用 `none` 加自包含任务说明；确实依赖最近讨论时传少量轮次，只有难以可靠摘取的决策背景才传完整历史。不继承历史时必须补齐用户已授权范围、适用 AGENTS/skill 路径和约束，不能只写「按上面方案」。其他运行时只用其实际支持的上下文选项。
- **共享目录不等于隔离副本**：确认子代理实际 cwd 和隔离方式。共享工作区时改动即时可见，无需复制回来或 cherry-pick；文件 owner 是协作约束，不是沙箱隔离。不能让代理自行切换分支、stash 或清理全仓；若运行时确实使用隔离工作树，由主会话在整合后重新验证受影响范围。
- **续接区分工具语义**：在提供 `collaboration` 的运行时，`send_message` 给运行中的代理补充信息，但不会唤醒已空闲代理；继续已有代理的任务用 `followup_task`。`wait_agent` 只通知有更新，需读取收到的消息；`list_agents` 用于状态不明时核实，避免反复轮询。其他接口按其工具说明做同等操作。
- **等待与中断**：派发后先推进主会话的独立工作，有结果通知时及时消费；没有独立工作时使用有界等待并保持用户进度更新。中断请求返回不等于所有 shell 子进程已经退出，换 owner 或恢复写入前核对代理和命令句柄，防止旧进程继续写入。
- **控制重复工作**：同一定位结果和验证证据通过原代理续接复用；主会话不边委派边重做同一搜索。默认由主会话安排一层有界子任务，确有新的独立任务和容量时才继续分派，避免每个角色递归建立一套代理链。摘要不再套一层摘要代理。

平台依据：[OpenAI Subagents 文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)；工具调用细节以当前会话 schema 为准。DevFlow 的角色 Markdown 是任务约束，不是 Codex custom agent 配置。

### 模型分级

下表是可用模型下的任务默认值，用于在满足质量要求时选择最经济的可用模型，不是价格排行榜，也不声称具体价差。

| 任务 | 默认请求模型与推理强度 |
|------|----------------------|
| 纯命令或小任务，直接工具执行 | 不派发子代理 |
| 已知路径查找、固定输入摘取、逐项回填与机械小改 | `gpt-6-luna`，`low` |
| 测试结果解释、diff 语义摘要、多份素材核对成文 | `gpt-6-luna`，`medium` |
| 有界常规实现，需理解局部逻辑 | `gpt-6-sol`，`medium` |
| 陌生调用链探索、遗漏影响排查或深入多步实施 | `gpt-6-sol`，`high` |
| 需求、设计、跨文件决策、最终验收 | 当前主会话，保留用户选择的模型 |

- 主代理先判断任务难度，选择满足质量的最经济可用模型；以工具声明或明确价格信息判断，不按模型名称臆测。派发前核对当前工具实际支持的模型 ID 和推理强度。没有经济信息或目标模型不可用时，使用已知合适的可用模型；没有合适的已知选项或工具不支持覆盖时继承默认配置。简要说明回退原因，不宣称降成本。
- 推理强度按[任务条件](./_command-models.md#推理强度)选择，不能仅凭 `code-scout`、`test-runner` 等角色名固定档位。已知符号检索与未知调用链探索、原样摘取测试计数与解释失败证据，不是同一种推理任务。
- 主会话识别为 `gpt-6-astra` 时，有界实施优先用 GPT-6 Sol，机械单元用 GPT-6 Luna；识别为 `gpt-6-sol` 时，机械单元可交给 Luna，只有可独立验收且值得并行的常规实施才另派 Sol。复杂且不可拆的判断由主会话完成。其他主模型或模型未知时，按任务复杂度和实际可用模型派发，不推断主模型身份或切换主会话。
- 工具支持 `spawn` 的 `model`/`reasoning_effort` 时实际传参。当前 collaboration 的完整历史 `fork_turns=all` 不能覆盖，因此通常用 `none` 加自包含任务说明，或仅传少量轮次；确实需要完整历史时继承并说明，不能假装降档。
- 每次派发都附简短报告，说明任务、请求模型和原因；工具未确认时不宣称实际计费或节省比例。
- 执行失败先区分命令/依赖问题与能力问题；环境错误不触发模型升级。能力不足由主会话补齐说明、缩小单元或必要时升档；已执行任务及证据应复用，不反复以同档模型重派。

### 任务角色

| 角色 | 读取时机 | 返回内容 |
|------|----------|----------|
| [code-scout](./roles/code-scout.md) | 定位范围较大的实现、调用方及参照代码 | 文件、关键行、相关度及原因 |
| [test-runner](./roles/test-runner.md) | 运行输出较多或可独立执行的测试 | 计数、退出码、失败证据及日志路径 |
| [diff-digest](./roles/diff-digest.md) | 超过 10 个文件或 800 行的 diff | 逐文件统计、结构性变化和待核实项 |
| [impl-worker](./roles/impl-worker.md) | 方案明确的独立实现单元 | 实际改动、验收结果和越界需求 |
| [doc-writer](./roles/doc-writer.md) | 大批素材成文或已确认方案回填 | 产物、要点核对和缺失素材 |

## 实施准入

四项全部满足才委派写代码：方案已经用户授权且具体到文件与函数；各单元没有共享修改文件或待定的中间产物；接口、字段和错误语义已经确定；有可执行的构建或测试命令验收。

按可独立验收的行为划分单元，同一行为的实现与对应测试交给同一个 owner；一个单元可以包含多个文件，不按文件逐个派发。派发前列出单元、允许修改文件、只读依赖和验收命令。同一文件只能有一个写入者；共享注册表、配置或聚合测试由主会话串行整合，不能同时编辑代理正在写的文件。

新建抽象、跨层契约变更和方案仍在演化的首版实现由主会话完成。独立单元可并行，依赖单元等前序完成并复核后再执行。测试共用数据库、端口或可写 fixture 时也要串行或隔离。

主会话核对实际 diff 和验收证据，处理越界需求、冲突及跨单元一致性；子代理自述不能代替验收。readonly 仓库不得通过 doc-writer 修改主仓需求文档。

## 素材和返回

小段必要素材直接放入任务说明；大型 diff 给出已核实的 base/head SHA、工作目录和精确取数命令，子代理自行读取，避免主会话为派发先加载全文。实现任务附已定方案，成文任务附骨架和素材。返回结论及必要证据，不回传整段日志或全文。

同批任务共用的环境条件由主会话先核实一次：工作目录、实际可用命令、需要的服务和可写临时目录；把结果传给子代理，隔离各自可写产物。不要传递凭据或完整环境变量。实际环境错误仍须如实回报。

所有角色按 [_evidence.md](./_evidence.md) 返回任务状态、范围和证据；派发时记录原有改动，验收时区分本轮修改与其他任务的修改。测试结果只有与当前相关内容及环境一致时才能复用，不能仅比较 HEAD。

优先续问已有子代理以补齐部分结果。按工具实际状态区分仍在运行、等待输入、完成、失败和中断；超时或观察窗口结束不能直接当成失败重新派发。缺失或被截断的结果标为 PARTIAL，不当成全部完成。反复截断时缩小单元或补充必要素材。

部分完成时保留已核实产物，向原代理补充缺失材料和剩余范围；只有确认原代理已停止且无法继续时，才把剩余部分交给新代理，并转交现有证据。一个单元阻塞只暂停依赖它的任务，其他独立单元可继续。

委派不扩大原任务授权。提交、推送、发布评论、合并及其他外部写入由主会话按用户授权处理。
