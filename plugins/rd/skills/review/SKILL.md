# 代码审查

执行模型：按[命令模型路由](../../shared/_command-models.md)中 `rd:review` 的档位执行；已作为执行子代理时不再次路由。

无子命令时审查 PR 代码；`comments` 拉取人工评审评论、生成修改方案并在授权范围内修改代码。需求评审用 `/rd:req-review`。

> **Audience:** Engineer
> 不受仓库角色限制，`readonly` 也可执行。
> GitHub 优先用已登录的 `gh`；Gitea 按 [_gitea_cli.md](../../shared/_gitea_cli.md) 检测 `tea`，未覆盖的接口用 curl。

## 命令格式

```text
/rd:review [PR-ID|REQ-XXX|QUICK-XXX] [--level=low|medium|high] [--auto]
/rd:review comments [PR-ID|REQ-XXX|QUICK-XXX]
```

参数含 `pass` 或 `reject` 时不执行任何评审或写入，只提示旧需求评审写法已改为 `/rd:req-review`。

## 通用前置

- 依赖已创建的 PR；未找到时提示先执行 `/rd:pr`。
- 参数给 PR ID 时直接使用；给需求编号时取需求文档 `branch`；都省略时从当前分支匹配。
- `gh` 只在已安装且 `gh auth status` 通过时可用。不可用时，公开仓库的只读查询可回退 REST API；私有仓库无凭据时报告限制并结束。平台写操作不可用时只展示本地报告与手动指引。

## AI 代码审查

### 1. 固定审查范围

按平台获取实际 PR 的 base/head 仓库、ref 和 SHA，fetch 两端并确认本地对象与记录 SHA 相符，固定 `BASE_SHA...HEAD_SHA`。使用 PR 实际目标分支，不用全局 `mergeTarget` 覆盖；fork PR 从 head 仓库获取。不切换或修改用户工作区。

用 `git diff --numstat` 和 `--name-status` 取得文件数、逐文件增删行和重命名。二进制行数记为未知，不当成零。

**文件分类**（先只看路径和后缀）：

| 类别 | 判定 |
|------|------|
| 非代码 | 文档；JSON/YAML/TOML/INI/环境配置；lock；明确的生成文件；`dist/`/`build/` |
| 展示层 | CSS/SCSS/Less/Stylus；静态资源与字体；文案和国际化；纯 HTML 模板 |
| 逻辑代码 | 其余文件；Vue/TSX/JSX 整体归入逻辑代码；测试文件是其子集 |

| 路由 | 判定 | 主会话读取方式 |
|------|------|------------------|
| 小 PR | 不超过 10 文件、800 行，且无未知行数 | 读全量 diff |
| 非逻辑为主 | 非代码+展示层至少 80%，逻辑部分不超过 10 文件、800 行 | 读逻辑 diff；其余看 numstat，并抽读改动最多的 3 个文件 |
| 大 PR | 其余 | 按 [_delegate.md](../../shared/_delegate.md) 用 `diff-digest` 定位，再执行完整审查 |

无法取得精确对象或 merge-base 时，说明未覆盖范围，不用工作区 diff 冒充 PR diff。

### 2. 读取审查依据并对照需求

按优先级读取项目 `AGENTS.md`、测试规范、需求文档的功能清单和业务规则。`docs/prompt/pr-review.md` 存在时合并其项目特有维度，缺失时静默跳过。

如有关联需求，检查状态、功能清单、接口需求、数据模型、文件清单、实现步骤、业务规则与关联需求是否和实际实现一致。未找到需求文档时说明并跳过。

### 3. 选择审查深度

`--level=low|medium|high` 显式值优先；否则按下表计分，输出 `深度：<level>（命中：<信号>）` 和 `文件分类：逻辑 n / 展示 n / 非代码 n`。

| 分值 | 信号 |
|------|------|
| +1 | 超过 30 文件或 2000 行 |
| +1 | 接口签名、DTO/表字段、错误码、配置项或依赖变化 |
| +1 | 涉及 migration/schema/SQL、鉴权/权限、支付或删除语义 |
| +1 | 逻辑代码有改动，测试改动行数不足逻辑代码的 10% |
| +1 | 改动涉及至少 3 个项目实际模块 |
| -1 | QUICK 需求或 hotfix 分支 |
| -1 | 非代码+展示层至少占已知改动行的 80% |

总分不大于 -1 选 `low`，0–1 选 `medium`，至少 2 选 `high`。未知行数不进入比例分母，需说明统计局限。深度只决定追踪程度，不能缩减变更文件覆盖。

### 4. 完整审查

- 小 PR 或非逻辑为主路由：主会话按选定深度审查已读 diff，必要时按行为或模块委派只读子任务。
- 大 PR：摘要只用于导航和需求对照，不能代替完整代码审查。按以下优先级选后端：
  1. 运行时暴露了可固定 base/head 的 Codex 专用只读 review 工具时，按实际接口使用。
  2. `codex exec review --help` 可用时，调用 [Codex review 适配器](../pr/scripts/run-codex-review.sh)，从标准输入传入自包含审查说明。适配器在 `HEAD_SHA` 的临时 detached worktree 中执行 `codex exec review --ephemeral --base <BASE_REF> -`，并校验 base ref 未变。
  3. 原生后端不存在或首次调用失败时，记录原因，按 [_delegate.md](../../shared/_delegate.md) 委派独立审查子任务。不修改用户 Codex 配置，不用同参数重复重试。

传给原生后端或子任务的说明必须自包含：固定范围、只审本 PR 引入的问题、所选深度的关注点、需求功能与业务规则、项目特有规范，以及输出文件行号、触发条件和后果。不传凭据、完整环境变量或无关文档。子任务按[统一证据契约](../../shared/_evidence.md)返回实际覆盖清单，主会话负责跨模块契约、去重和关键判断复核。

结果只列本 PR 引入且有证据的缺陷。每条附触发条件、后果、文件行号和证据；原有问题归为信息；风格偏好不自动阻塞。原生优先级不机械代替 DevFlow 分级：P0/P1 默认阻塞，P2/P3 仍按实际后果判断；会造成错误行为、安全、数据或兼容性问题的缺陷均应阻塞。不完整的审查必须报告未审范围，不得声称通过。发布评论或合并前重新核对 head SHA，变化时补审增量。

### 5. 输出与平台写入

报告分为「代码审查」和「需求文档同步」；问题分为「阻塞」、「建议」和「信息」。

默认只展示结果并结束。只有用户明确要求提交评论、使用 `--auto` 或已有等价授权时才发布；`--auto` 只授权本次审查评论，不授权 Approved 或合并。零问题也不自动发布。`repoType=other` 只本地展示。

发布时保留所有阻塞、关键建议和文档关键缺失，去除信息级备注与过程信息。无阻塞时也只继续用户已授权的 Approved 或 merge 动作。

## `comments` — 按人工评审评论修改代码

1. 复用 [PR 子命令流程](../../shared/pr-ops.md#comments--只读查看评论) 的拉取和过滤规则。无可处理评论时结束。
2. 行内评论按 `path` + `line` 读相关上下文；整体评论按内容定位，范围不明时委派 `code-scout`。
3. 逐条判定「可执行」或「需讨论」，给出文件位置、评论摘要、具体修改方案和判定理由。
4. 用户已明确要求处理评论时，实施「可执行」项并验证；「需讨论」项只列出，不猜测方案。只要求查看或分析时不改文件。
5. `--auto` 不适用于本子命令，不扩大修改授权。修改完成后提示 `/rd:commit`。
