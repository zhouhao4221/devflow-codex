## 统计口径与节约率

从当前任务及递归子代理的本地 rollout 中，只选目标 root_turn_id 的 token_usage_record。按 response_id 全局去重后累加单次 usage，不累加 turn_token_usage、thread_token_usage 或 token_count 累计快照。输入已包含缓存输入；输出已包含 reasoning_output_tokens，不重复加总。每条记录已校验 total_tokens = input_tokens + output_tokens。未读取或导出其他任务正文、账号凭据。

节约率公式：(同任务旧版总 token − 同任务新版总 token) / 同任务旧版总 token × 100%。

**当前节约率：无法计算（缺少可比旧版基线）。** 先前的 dry-run、clamp 修复和新增 tags 测试，与本轮的 ranges/records 并行实施、异常验收并非同一任务，直接相减没有意义；缓存命中率也不等于节约率。

还需要在相同代码起点、任务、模型、推理强度、权限和验收标准下，用新旧指导分别重复执行，收集完整执行树的 usage。不同范围的研发统计不应作为这些任务的对照。
